# EBP Managed Mail Server (Stalwart)

This directory runs the mail server behind EBP's "Get started" onboarding
wizard. Users pick `username@<MAIL_DOMAIN>`; the EBP key server (on Render)
creates the mailbox here through Stalwart's JMAP management API (`POST /jmap`).

Render cannot host this part: Render exposes only one HTTPS port to the
internet (no inbound 25/465/587/993) and blocks outbound port 25 on every plan.

```
clients --(signed signup, HTTPS)--> key server (Render) --(JMAP x:Account/set)--> Stalwart (VPS)
clients --(IMAP 993 / SMTP 465)---------------------------------------------> Stalwart (VPS)
```

## 1. Buy the domain

Any registrar works; mailbox count is unlimited because Stalwart hosts the
mail. Cloudflare Registrar (at cost, ~$10.50/yr for `.com`) or Porkbun are the
easiest. Recommended name: `pqpost.com`.

## 2. Get a VPS with port 25

- **Hetzner Cloud CX22** (~4 EUR/month, 2 vCPU, 4 GB). Outbound port 25 is
  blocked on new accounts; open a support request to unblock it after the first
  invoice is paid.
- **Vultr** is the fallback (also needs a port 25 unblock request).
- **Avoid DigitalOcean**: it blocks SMTP and rarely unblocks.

Install Docker and the compose plugin, then open TCP 25, 443, 465, 587, 993 in
the firewall. Keep 8080 closed (it is bound to 127.0.0.1).

## 3. DNS records

Replace `pqpost.com` and `203.0.113.10` with your domain and VPS IP. On
Cloudflare, every record pointing at the VPS must be **DNS only** (grey cloud).

| Type | Name | Value |
| --- | --- | --- |
| A | `mail` | `203.0.113.10` |
| MX | `@` | `mail.pqpost.com` (priority 10) |
| TXT | `@` | `v=spf1 mx -all` |
| TXT | `_dmarc` | `v=DMARC1; p=quarantine; rua=mailto:postmaster@pqpost.com` |
| TXT | `<selector>._domainkey` | value generated by Stalwart (step 5) |

Optional: MTA-STS (`_mta-sts` TXT + `mta-sts.` host) and TLS-RPT once mail flows.

**Reverse DNS (PTR):** in the VPS provider panel set the IP's PTR to
`mail.pqpost.com`. Without it, Gmail and Outlook will reject or spam-folder mail.

## 4. Start Stalwart

```bash
cd mail-server
cp .env.example .env   # edit MAIL_HOST
docker compose up -d
docker compose logs stalwart   # prints the first-run admin credentials
```

Open the web admin through an SSH tunnel:

```bash
ssh -L 8080:127.0.0.1:8080 root@203.0.113.10
# then browse http://localhost:8080
```

## 5. Configure Stalwart (web admin)

1. Finish the bootstrap wizard: hostname `mail.pqpost.com`, RocksDB storage.
2. **TLS:** enable the Let's Encrypt ACME provider for `mail.pqpost.com`.
3. **Domain:** create `pqpost.com`, then generate a DKIM key and publish the
   TXT record it shows. This classical Stalwart key is temporary. EBP should
   later own DKIM signing and move it to a post-quantum algorithm once
   receivers can verify one. See
   `wiki/analysis-ebp-managed-email-onboarding.md`.
4. **Submission policy:** require authentication on 465/587; never relay for
   unauthenticated clients.
5. **Limits:** set an outbound rate limit per account (e.g. 100 messages/hour)
   and a default disk quota.
6. **Reserved accounts:** create `postmaster@` and `abuse@` and route them to
   your own inbox.
7. **API key for the key server:** create an admin-scoped API key (or a custom
   role) with at least `sysAccountCreate`, `sysAccountUpdate`,
   `sysAccountDestroy`, `sysAccountGet`, and `sysDomainGet`. Copy the token.
8. Look up the domain's JMAP id (Management > Domains, or `x:Domain/get`).

## 6. Configure the key server (Render env vars)

| Variable | Example | Purpose |
| --- | --- | --- |
| `MAIL_SIGNUP_ENABLED` | `true` | Turns on `/api/v1/mail/signup` (default off) |
| `MAIL_DOMAIN` | `pqpost.com` | Address domain |
| `MAIL_HOST` | `mail.pqpost.com` | IMAP/SMTP host returned to clients |
| `STALWART_ADMIN_URL` | `https://mail.pqpost.com` | Stalwart HTTPS base URL |
| `STALWART_ADMIN_TOKEN` | `...` | API key from step 5.7 |
| `STALWART_DOMAIN_ID` | `b` | Optional JMAP domain ID hint. Signup verifies its domain name and looks up other requested domains by name. |
| `MAIL_QUOTA_BYTES` | `1073741824` | Per-mailbox disk quota (default 1 GiB) |
| `MAIL_E2E_SECRET` | long random string | Lets `deno task test:pqpost-mail` create and delete only `e2e` plus digits addresses |

Optionally point the existing verification mailer at Stalwart too:
`SMTP_HOST=mail.pqpost.com`, `SMTP_PORT=465`, `SMTP_SECURE=true`,
`SMTP_USER=noreply`, `SMTP_PASS=...`, `SMTP_FROM=noreply@pqpost.com`.
Set `PUBLIC_BASE_URL` to the HTTPS key-server URL. If verification delivery
is unconfigured, publishing the claim still succeeds and reports the delivery
problem. The owner can request verification after configuring delivery.

For `pqpost.com`, mailbox names shorter than nine characters require a confirmed
purchase when paid signup is enabled; otherwise they remain unavailable. Existing
mailboxes are unaffected. The test domain follows the same rule.

## 7. Smoke test

```bash
curl -s https://<key-server>/api/v1/mail/signup/config
# {"enabled":true,"domain":"pqpost.com","imap":{...},"smtp":{...}}
```

Then run the onboarding wizard in the GUI or mobile app and send a message to
an outside Gmail address. Check headers for `dkim=pass`, `spf=pass`,
`dmarc=pass`.

## Live mail test on test.pqpost.com

`deno task test:pqpost-mail` creates two disposable
`e2e<digits>@test.pqpost.com` mailboxes through the key server, sends a unique
message over authenticated TLS SMTP (465), checks delivery over TLS IMAP
(993), and deletes the mailboxes. It first checks the key server's signup
configuration and refuses to mutate a server advertising another domain or
unexpected transport settings. The default key-server URL is
`http://127.0.0.1:8789`; there is no production Render fallback.

### Prerequisites

1. Add `test.pqpost.com` as an enabled domain in Stalwart, with its own DKIM
   keys. Continue using `mail.pqpost.com` as the connection hostname.
2. In the Cloudflare `pqpost.com` zone, add an MX record named `test` pointing
   to `mail.pqpost.com` at priority 10, an SPF TXT record named `test` with
   `v=spf1 mx -all`, and both DKIM TXT records shown by Stalwart for the test
   domain. An optional `_dmarc.test` TXT record can use
   `v=DMARC1; p=none; rua=mailto:postmaster@pqpost.com` while verifying setup.
3. Use a Stalwart management token with account create, query, read, update,
   and destroy permissions, plus domain lookup. Account lookup and update let
   signup recover if the mailbox was created but the response was lost.
   Keep the token in the ignored configuration file below.
   A token restricted to the test domain is preferable when supported.

### Local key server

From the repository root:

```sh
cp mail-server/.env.test.example .env.pqpost-mail.local
# Fill STALWART_ADMIN_TOKEN and MAIL_E2E_SECRET in that file.
# Generate a separate test secret with: openssl rand -hex 32
deno task server:pqpost-mail-test
```

This task binds the key server to `127.0.0.1:8789`, forces the mail domain to
`test.pqpost.com`, and uses `test-results/pqpost-mail-e2e.sqlite` regardless of
production database settings in `.env`. It also clears any configured
`STALWART_DOMAIN_ID` so the test domain is looked up by name. Public signup
rate limits are disabled on this local test instance. Production services
are not reconfigured.

Keep the database between runs: it records the remote account IDs used to
clean up abandoned test mailboxes. Stop the server with Ctrl+C when finished.

In another terminal:

```sh
deno task test:pqpost-mail
```

Both tasks load `.env.pqpost-mail.local` before `.env`; existing process
environment variables take precedence. The runner tracks each successful
signup immediately, so failure of the second signup still cleans the first.
At startup it also sweeps `e2e<digits>` mailboxes at least six hours old from
this test key server's database and configured domain. Do not run concurrent
tests that keep mailboxes alive for six hours or longer.

These tests share the Stalwart VPS with production but use a separate mail
domain and local identity database. Internal delivery does not require
outbound port 25 and does not establish external deliverability or prove
public DNS/DKIM authentication works. Published identities remain in the
test database; cleanup removes their email details and remote mailboxes.

Run the focused regression tests without mail credentials or live services:

```sh
deno task test:pqpost-mail:unit
```

## Operations notes

- **Deliverability:** a new domain and IP start with no reputation. Expect
  spam-foldering for the first weeks; keep volume low and DMARC aligned.
- **Abuse kill switch:** set `MAIL_SIGNUP_ENABLED=false` on Render to stop new
  signups instantly. Existing mailboxes keep working.
- **Backups:** snapshot the `stalwart-data` and `stalwart-etc` volumes.
- **Upgrades:** the image is pinned to the `v0.16` minor series; read
  Stalwart's `UPGRADING/` notes before moving to a new minor version.

## Paid short-address checkout

Paid signup is disabled unless `MAIL_PAYMENT_ENABLED=true` and all payment
configuration is valid. Names of 3–8 characters have a one-time USD price;
longer names remain free. Configure `MAIL_PAYMENT_PRICES_CENTS` as JSON with a
positive integer price for every length `3` through `8`, strictly decreasing
as the length increases. Configure `MAIL_PAYMENT_ASSETS` as a JSON array of
objects with `network`, `symbol`, `recipient`, `unit`, and `decimals`. For ETH,
use unit `native` and 18 decimals; for ADA, use `lovelace` and 6 decimals. For
Ethereum tokens, `unit` is the token contract address; for Cardano native
assets it is the lowercase policy ID concatenated with the hex asset name.
Only configure independently verified canonical asset identifiers and wallet
addresses. Accepted symbols are ETH, USDC and USDT on Ethereum, and ADA, USDM,
USDA, USDCx, DJED and iUSD on Cardano. Stablecoins are valued at $1 each.

Set `MAIL_PAYMENT_ETH_RPC_URL` to an HTTPS JSON-RPC endpoint,
`MAIL_PAYMENT_BLOCKFROST_KEY` to the appropriate Blockfrost project key, and
`ETHEREUM_ALCHEMY_API_KEY` to an Alchemy API key. ETH and ADA quotes read
Chainlink through that key. A new ETH/USD reading from Ethereum mainnet must be
at most 70 minutes old. A new ADA/USD reading from Polygon mainnet must be at
most 5 minutes old. Checkout shares a two-hour database cache across users and
server processes using the same database. A quote request can refresh its asset
once every two hours. The database records the most recent attempt and the most
recent successful cache write for each asset. If a refresh fails, new quotes
for that asset are unavailable until its next refresh window. Other assets can
refresh independently. Start a payment within the 30-minute quote. The following two hours allow delayed hash
submission, replacement hashes from a wallet fee bump, and confirmation.
Confirmation counts default to 5 Ethereum blocks and 2 Cardano blocks; set
`MAIL_PAYMENT_ETH_CONFIRMATIONS` and `MAIL_PAYMENT_CARDANO_CONFIRMATIONS` to
positive integers to change the thresholds for new orders.
Orders still awaiting a valid confirmation at the end of the grace period
require manual review. To pause new quotes while existing payments finish,
disable the payment catalog and keep the verification credentials for each
network with outstanding orders.
Keep payment records and the database durable and backed up. Never put spending
keys on the key server. Use only a receiving wallet and wallet infrastructure
capable of handling the required on-chain message and token transactions.

The production checkout expects its key server at
`https://keys.pqpost.com`. `https://pqpost.com` and
`https://test.pqpost.com` may call that server. Set the Render service's
`PUBLIC_BASE_URL=https://keys.pqpost.com` so verification emails use the
custom domain. If `EXPECTED_HOSTS` is configured, include `keys.pqpost.com`.
For payment testing, use
the local test server described above, which serves checkout at
`http://127.0.0.1:8789/checkout.html` and uses the existing Stalwart service
for `test.pqpost.com`. Configure test assets with `ethereum-sepolia` and/or
`cardano-preview`, separate testnet receiving addresses and the corresponding
test-token identifiers. The application rejects mixed mainnet/testnet asset
configurations, and testnet orders cannot purchase production addresses.

To exercise a complete paid signup, fill the payment settings in the same
ignored `.env.pqpost-mail.local` file, enable payments, and restart
`deno task server:pqpost-mail-test`. In another terminal run, for example:

```sh
deno task test:pqpost-payment ethereum-sepolia ETH
# or, with a configured Preview receiving address and provider:
deno task test:pqpost-payment cardano-preview ADA
```

The production key server keeps `MAIL_DOMAIN=pqpost.com`. Test addresses are a
separate mode: a client sends `x-ebp-mail-mode: test` (or `?mode=test` on a
GET) and the same server offers `test.pqpost.com` instead. Configure
`MAIL_TEST_PAYMENT_ENABLED=true`, `MAIL_TEST_PAYMENT_ASSETS` with only
`ethereum-sepolia` and `cardano-preview` recipients, `MAIL_TEST_PAYMENT_ETH_RPC_URL`,
and `MAIL_TEST_PAYMENT_BLOCKFROST_KEY`. Prices fall back
to the `MAIL_PAYMENT_*` values when the test-specific ones are unset. ETH and
ADA quotes use `ETHEREUM_ALCHEMY_API_KEY` in both modes. Normal
requests never see the test domain. The mobile app shows those addresses only
while its test-mail setting is on, then sends the buyer to
`https://test.pqpost.com/checkout.html` to pay from a computer or a wallet
browser.

### Mint placeholder stablecoins

#### Browser wallets

Run the local mint page on the computer that has your browser wallets.
Install Deno, and put a Blockfrost Preview project ID in
`scripts/testnet-mint/.blockfrost-key` (one line, the ID only). That file is
gitignored. From the repository root:

```sh
deno task mint:testnet
```

Open [the local mint page](http://127.0.0.1:8790/) in the browser profile with
your wallets. Switch the Cardano wallet to Preview. Fund the wallets with
Sepolia ETH and Preview ADA for fees. Mint `tUSDC` and `tUSDT` individually
on Sepolia and mint `tUSDM`, `tUSDA`, `tUSDCx`, `tDJED`, and `tiUSD` in one
Preview transaction. Your extensions hold the signing keys. The local server
compiles the Ethereum contract and builds the unsigned Cardano transaction.
It listens only on `127.0.0.1` and is outside the deployed website.

Click **Check** for each submitted mint to load its confirmed asset IDs.
On a confirmed Sepolia token, click **Add to wallet** so the extension tracks
that contract. The page lists every asset with the `network`, `symbol`,
`recipient`, `unit`, and `decimals` the key server requires. Enter your
checkout receiving addresses and download the payment asset JSON.
Include native ETH and ADA in the export if you accept them for checkout.
Use faucet funds for those two native coins. Set the resulting array once in
`MAIL_TEST_PAYMENT_ASSETS` for hosted test mode, or `MAIL_PAYMENT_ASSETS` for a
server dedicated to `test.pqpost.com`.

#### Command line

From the repository root, use an Ethereum wallet funded with Sepolia ETH and a
Cardano wallet funded with Preview ADA. The script mints Sepolia ERC-20 tokens
`tUSDC` and `tUSDT` and Cardano Preview native assets `tUSDM`, `tUSDA`, `tUSDCx`,
`tDJED`, and `tiUSD`. Each uses six decimal places in checkout and is quoted
at one test dollar per token.

Set the following variables in your shell before running the script:

| Variable | Value |
| --- | --- |
| `MAIL_TEST_PAYMENT_ETH_RPC_URL` | Sepolia RPC URL |
| `SEPOLIA_MINT_ACCOUNT` | Funded Sepolia keystore account imported with Foundry's `cast wallet import` |
| `SEPOLIA_MINT_TO` | Sepolia address for the tester receiving the tokens |
| `SEPOLIA_PAYMENT_RECIPIENT` | Sepolia address that will receive checkout payments |
| `MAIL_TEST_PAYMENT_BLOCKFROST_KEY` | Blockfrost project ID for Cardano Preview |
| `PREVIEW_MINT_KEY_FILE` | Path to a file containing the funded Lucid wallet's bech32 payment signing key (`ed25519_sk…`) |
| `PREVIEW_MINT_TO` | Preview payment address for the tester receiving the tokens |
| `PREVIEW_PAYMENT_RECIPIENT` | Preview payment address that will receive checkout payments |

With Foundry and Deno installed:

```sh
deno run --allow-env --allow-net --allow-write --allow-run=forge \
  scripts/mint_test_stablecoins.ts ethereum-sepolia tUSDC 1000 > sepolia-tusdc.json
deno run --allow-env --allow-net --allow-write --allow-run=forge \
  scripts/mint_test_stablecoins.ts ethereum-sepolia tUSDT 1000 > sepolia-tusdt.json
deno run --allow-env --allow-net --allow-read \
  scripts/mint_test_stablecoins.ts cardano-preview 1000 > preview-assets.json
jq -cs 'add' sepolia-tusdc.json sepolia-tusdt.json preview-assets.json
```

Set `MAIL_TEST_PAYMENT_ASSETS` to the resulting JSON array for the hosted test
mode, or set `MAIL_PAYMENT_ASSETS` for a server dedicated to
`test.pqpost.com`. To keep ETH or ADA selectable, include their existing
entries in that same array. The server uses this list to populate both desktop
and mobile coin selectors and validate new orders. Import the Sepolia tokens
by contract address if your wallet requires it. The tester needs Sepolia ETH
or Preview ADA to cover transaction fees.

Wait for mint transactions to confirm before starting checkout. Another
Sepolia deployment creates a new contract address. To fund more testers with
the same tokens, transfer from the existing supply. A new Preview mint with
the same signing key reuses the same policy and asset IDs.

Deploy the hosted test checkout from the repository root:

```sh
python3 scripts/with_cloudflare_env.py npx wrangler deploy --config wrangler.test.jsonc
```

Set `CLOUDFLARE_API_TOKEN` (and `CLOUDFLARE_ACCOUNT_ID` if needed) in the
environment or the ignored root `.env` file. `wrangler.test.jsonc` declares
`test.pqpost.com` as a custom domain of the `pqpost-test-checkout` Worker, so
deployment provisions the web DNS record and HTTPS certificate as well as the
static files. The email domain's MX record alone does not make checkout
reachable. Keep that MX record for mail delivery. In the Cloudflare dashboard,
the equivalent setup is Workers & Pages → `pqpost-test-checkout` → Settings →
Domains & Routes → Add → Custom domain → `test.pqpost.com`.

The test refuses non-loopback key servers, non-test mail domains and mainnet
assets. It creates a disposable eight-character `e2e` test name and prints a
local checkout link. Connect a testnet wallet in checkout, review the generated
transaction, and approve it in your wallet. Checkout records the transaction ID
and shows confirmation progress. The script waits for confirmation, creates the
paid test mailbox, and cleans it up through the authenticated test-only cleanup endpoint. It never
holds a blockchain spending key. If cleanup reports an error, inspect the
isolated test server before retrying. Use `deno task test:pqpost-payment:unit`
for the safety checks without a wallet or network.

The order reference is a checkout capability: keep checkout links private.
The on-chain payment message is a separate public reference. If a transaction
is late, insufficient, unmatched, or requires manual review, do not resend
payment without consulting support. Recovery uses a fresh signature from the
original identity; a confirmed order remains valid if mailbox creation fails.
